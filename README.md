# 凉城证据簿

用于城市降温与节水行动的观测口径、暴露人口、保护缺口和比较分析。它保留资料修订来源，区分缺测与零风险，支持行动组合的假设比较与带审核证据的本地发布。分析是描述性证据，不自动证明行动具有因果效果。

运行环境为 Python 3.11 及以上，仅使用标准库和自带 SQLite，无第三方依赖。资料不需联网。命令从本目录执行；Windows 可将 `python` 换成已安装的 Python 路径。

```bash
python -m unittest discover -s tests -v
python -m compileall -q climate_ledger
python acceptance.py
python -m climate_ledger --database city.sqlite3 ingest examples/city.json
python -m climate_ledger --database city.sqlite3 ingest examples/venue.json
python -m climate_ledger --database city.sqlite3 analyze examples/exposure.json
python -m climate_ledger --database city.sqlite3 compare examples/study.json
python -m climate_ledger --database city.sqlite3 plan examples/portfolio.json
python -m climate_ledger --database city.sqlite3 equity examples/exposure.json
python -m climate_ledger --database city.sqlite3 priorities examples/exposure.json
python -m climate_ledger --database city.sqlite3 diagnose examples/exposure.json
python -m climate_ledger --database city.sqlite3 operations examples/operations.json
python -m climate_ledger --database city.sqlite3 audit
```

`examples/` 全部是本地合成城市资料，不代表真实居民、观测站或研究结论。`city.json` 中资料包由 `id`、`source` 和 `records` 构成，每条资料含 `kind` 与 `data`。资料类型包括行政区、指标、站点、人口、行动及逐日观测，以及场所服务时段（`window`）、服务记录（`service`）、临时停用（`closure`）与替代安排（`arrangement`）。精确字段以该合成资料及 `formats.py` 的 CSV 列契约为准。

新对象从修订1开始；同修订只能重送相同内容，高修订由同一资料来源提交。整个资料包通过业务关联检查后才入账；一个对象不合格会拒绝整包。资料包编号绑定原始内容摘要，重送不新增水位，同编号更换内容会拒绝。观测身份是站点、指标与日期，其他对象使用稳定编号。此版本不支持删除资料、改变来源所有权或并行来源竞选。

所有时间区间首尾均包含，按本地业务日期解释，没有小时级时区换算。站点在有效期内归属一个固定行政区，指定支持指标和覆盖权重。同区同指标同时有效站点权重总和不能超过1。有效覆盖是有效观测的绝对权重和，缺站不能通过重新归一化假装完整；通过覆盖门槛后才以有效权重均值形成区日值。温度支持 C/F，水量支持 L/m3，能源支持 kWh/MWh，转换到指标标准单位后检查合理值域。`valid` 可用，`suspect` 排除，`missing` 必须配 `null`。高异常方向使用大于等于阈值，低异常方向使用小于等于阈值。

人口按行政区、人群、有效期登记，人口为零是已知资料，同组有效期不重叠。该行政区所有已登记群体都被视为分析需要的固定分组；某日少一组即人口资料不完整。新增具有不同历史覆盖的新群体需要先明确全期分母，不能把缺失默认为零。脆弱度是1到10的业务权重，不是患病概率。

行动可以处于计划、生效、暂停或结束状态，只有生效且在有效期内的行动参与保护。每个行动对应一个行政区、指标和设施。行动可选带 `claims` 份额列表，引用本设施的服务时段；没有 `claims` 的旧式行动按整日能力处理，不需要补全小时记录，其标准服务日按 08:00 至 20:00 折算。同设施相交日期不能同时承诺多项生效行动：任一行动没有 `claims` 即整日互斥；双方都有 `claims` 时按时段容量裁决，只有重叠部分竞争同一容量，重叠份额合计不能超过时段容量。先按行动优先级、编号分配，再按人群脆弱度与群体名分配，保护数不超过尚未保护的有效人口。没有危险的日期不消耗保护容量。当前仅以互斥人群计数估算保护，不记录个人身份。

场所通过 `window` 登记某日可用服务时段与容量，同设施同日时段不能重叠，也不能落在已被按日行动占用的设施当日。`service` 记录匿名群体片段、人数、实际开始结束与状态：预约（reserved）与未到场（no_show）不计保护，到场（arrived）与完成（completed）按记录的人时计保护，被否定（repudiated）的记录不再计入但保留在历史中。某行动某日一旦存在服务记录，该日保护即以记录为准，不再按容量估计；没有记录时按可用容量比例估计。`closure` 登记临时停用的发生与确认时间，停用界限等于实际发生时刻，确认较晚时仍按发生界限解释服务；停用只截断尚未交付的容量，已经完成且未被否定的保护不可因改排而删除。`arrangement` 把未兑现承诺的群体片段改排到同日其他时段，状态为提议、确认或撤回；安排是人工决定的事实记录，系统不自动创建、移动或删除，守恒性（不超过承诺减去已服务与未到场）与可执行容量在运营视图中派生，不阻断入账，保护额度在计算中截顶。替代安排的服务通过 `arrangement` 字段关联，保护计入原承诺所在行政区，不能跨区制造人口，也不能让两个行动对同一批人各算一次成功：同一时段上确认的安排会占用其他行动份额的可用容量。

暴露分析按实际人时折算保护：每人每日的需求时数等于行动当日承诺的服务跨度，交付人时除以需求时数得到保护人日当量，未兑现部分形成未保护人时与缺口人数。研究资格与保护事实一致：存在未兑现承诺的日期标记为中断（interrupted），不能因同区仍有其他生效行动就把中断日期当作完全受保护，等待替代或已有交付记录的对照区日也不算干净对照。

暴露结果保留逐日来源、质量、人口与行动依据；不完整区日的暴露是未知，汇总只标明已知部分并清空完整口径比例。加权负担是未保护人数、阈值距离与人群脆弱度的乘积，不跨不同指标量纲相加。缺观测会结束当前可确认的连续事件，但终点标为未知，不能宣称危险已经结束。公平性结果利用指标合理值域形成负担上下界，区间不是置信区间，分母缺失时不作确定排序。

比较研究在前后两期内分别按同日、天气差容限寻找对照，同阶段的对照区日最多使用一次。对照存在行动、前期行动区已启用、后期行动区尚未启用、人口为零或资料不完整的日期会排除并说明原因；保护中断的后期日期与已有交付或未兑现记录的对照区日同样排除。估计是后期和前期配对单位人口负担差的变化，配对不足不出数值。候选行动组合以实际联合保护结果比较，遵守预算和设施承诺，已保护群体不重复计效。组合结果只是假设，不修改已入账行动；一次最多比较16个候选。

`draft` 根据分析条件生成草稿并绑定入账水位、资料清单和摘要，独立审核人用摘要确认后才允许 `publish`。分析不完整、无有效人口或研究配对不足时不能审核发布。资料更新使所有旧草稿过期；旧发布内容仍保留，并标明不再是当前资料。专题发布需要提供期望的前序编号，避免覆盖别人刚签发的版本。`export` 以原子替换写出发布文件，`verify` 检查内容摘要；这是文件完整性检查，不是数字签名或外部身份认证。

`reconcile` 在相同分析条件下核对两个入账水位，说明哪些资料修订和区日结果变化，不能将该差异当作时间趋势。`operations` 按设施给出运营视图：各时段被谁占用、每次停用影响的未兑现承诺、替代安排后的缺口人数与未保护人时，以及各安排可执行与不可执行的部分和原因；再导入更早发生的停用或更正到场事实时，只重审受影响承诺，已确认安排不被自动改排。`export-csv` 导出资料快照，`ingest-csv` 可读单类资料，数组列使用 JSON 数组。`backup` 生成可直接重新打开的一致数据库副本，拒绝覆盖已有文件。`audit` 检查历史资料关联、修订顺序和发布证据链。数据账是本机受信文件；本工具没有网络账号系统，不应用于替代多人访问权限控制。

目录中 `observatory/` 负责指标、站点和观测有效性，`residents.py` 负责人口分母，`adaptation.py` 负责行动资格和保护容量，`venue.py` 负责场所时段、服务记录、停用与替代安排的事实与运营视图，`analysis/` 组织暴露、研究、组合与差异分析，`publication.py` 负责审核与专题发布，`ledger.py` 维护不可变修订，`application.py` 连接业务事务。测试按这些业务边界组织，包含跨边界更正、失败回滚、发布冲突和备份恢复。
